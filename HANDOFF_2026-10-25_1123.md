## 3. Switch bug fix and rollback safety

### 3.1 Root cause

`switch_variant.ps1` called the external `powershell -File install_mod.ps1` with
`-RuOnly:$RuOnly`. When a `SwitchParameter` crosses the external `powershell.exe`
boundary it becomes a string (`False`), so `install_mod.ps1` failed with:

```
Cannot process argument transformation on parameter 'RuOnly'.
Cannot convert value "System.String" to type "System.Management.Automation.SwitchParameter"
```

The failed run had **not** written anything: `~mods` still held exactly the p11 carrier,
font v3 and manifest with the expected SHA256s before this fix.

### 3.2 Fix

- `switch_variant.ps1` now builds an argument array.
- `-RuOnly` is appended **only when the switch is true**.
- `-Tips` is appended only when non-empty.
- `Carrier` and `Font` are plain strings and were checked; no other forwarded switch exists.
- `install_mod.ps1` gained optional `-ModsPath` so installs can be exercised in temp folders.
- Before installing, `switch_variant.ps1` byte-copies the current `~mods` to
  `build/install_backup/<variant>_<stamp>/` and records a hash manifest.
- On any install or verification failure, `restore_mods.ps1` verifies every backup hash
  before touching `~mods`, removes only project pak/manifest files, restores the backup,
  checks the exact set and hashes, and prints `ROLLED BACK TO <previous set>`.
- `restore_mods.ps1` refuses to delete unknown files, so a foreign file in `~mods` aborts
  the rollback instead of being silently removed.
