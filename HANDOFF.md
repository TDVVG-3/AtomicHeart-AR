## 2. Problems (and what I did)

1. `scripts/batch_plan.ps1` crashed on its first run: the `-f` operator inside a method-argument list is parsed as extra arguments. Fixed by building the line with `-join`. (Known PowerShell gotcha, now also visible in the script.)
2. `scripts/batch_apply.ps1 -All` reported "distinct English -> Arabic: 0": the switch never enumerated the chunk files. Fixed; `-All` now globs `chunk_*_ar.tsv`.
3. PowerShell `@{}` keys are case-insensitive: `CONSUMABLES` and `Consumables` are different master rows but collided and aborted the apply (`conflicting Arabic for the same English string: Consumables`). Fixed by switching the map to `Dictionary[string,string]` (ordinal). The same bug in the planner's occurrence index had silently marked `Off` (mixed case) as already translated, so it was never sent to a chunk; the 5 rows were supplied through the new `localization/working/batch1/extra_ar.tsv` override and applied. Recorded as KI-023.
4. 17 pure-format rows (`{Class},  {Message}`) had been applied with the Arabic comma as their only non-Latin character and then failed the validator ("Arabic contains no Arabic letter"). The checker and applier now use the validator's Arabic-letter class; stale values are reset to UNTRANSLATED and the rows are recorded as copy-class.
5. The first p5 build failed the round-trip check with 15 mismatches: their Arabic ended in a space and the UnrealLocres export/import strips trailing whitespace. Fixed with `scripts/trim_trailing_ws.ps1` (trailing spaces are invisible in game); the second build is clean. Recorded as KI-024.
6. 4 rows used a transliterated `Neuropolymer` instead of the glossary form; fixed through the data-driven `localization/working/tm_fixups.tsv` (no Arabic typed inside a script).
7. A translator pass left 144 UI rows above 1.2x the English; a dedicated shortening pass fixed 86 of them (guarded against token/digit loss), leaving 112 warnings of which only 9 are above 1.4x (8 are proper names or glossary terms).
